Why vio

Coding agents can git checkout.
Servers can't.

When an agent edits code, every mistake is one revert away. On a live server, a single bad firewall rule can lock you out for good. vio is designed around that difference.

A general agent with a shell

Fine for a repo. Risky for production.

  • Runs raw bash -c strings the model wrote
  • Safety rules live in a prompt and can be talked around
  • No undo and no diff for system state
  • Log files can steer it (prompt injection)
  • Secrets end up in the model's context

vio

Designed for machines you can't afford to break.

  • Typed tools with dry-runs, diffs, and rollbacks
  • Deterministic policy engine has the final say
  • Plans are hashed, approved, then applied under guard
  • Host data is data; arguments it supplies need your confirmation
  • Output is redacted before anything reaches the model
How it works

Six steps between a prompt and production

The model only proposes changes. A deterministic engine you can audit executes them.

  1. Observe

    The model investigates with read-only tools: ports, logs, configs, packages.

    model

  2. Plan

    Proposed changes become typed actions with diffs, risks, and rollbacks.

    model → code

  3. Policy

    Hard rules in code. "Never close the port I'm connected on."

    code

  4. Approve

    You approve the whole plan. Approval is bound to the plan's hash.

    you

  5. Guarded apply

    Backup, validate, apply, verify with a fresh login. Revert on failure.

    code

  6. Audit

    Every step goes to a hash-chained, tamper-evident log.

    code

The model proposes. The code disposes.

Lockout guard

It won't lock you out of your own server

Before touching SSH, the firewall, users, or keys, vio schedules an automatic revert on the host itself. Then it proves access with a brand-new SSH login. Only after that does it cancel the revert.

Features

Small binary, serious guarantees

Agentless

Any Linux host you can SSH into. Nothing installed, strict host-key checks.

Plan → apply

Reviewable plan files you can diff, commit, or hand to a teammate for approval.

Security baseline

vio check runs CIS-inspired checks with no LLM, so it works offline and in CI.

Secrets stay local

Keys, tokens, and .env values are redacted before the model sees them.

Policy as code

Hard denies the model can't argue with. Write your own rules in policy files.

Rollback

Every change stores its own undo. vio rollback reverts an applied plan.

Audit chain

A hash-chained JSONL log of every observation, approval, and command.

Any model

Anthropic, OpenAI-compatible endpoints, OpenRouter, or local models via Ollama.

Roadmap

Built in the open

Each phase has an exit criterion. A phase is finished when the criterion is met, not when the code exists.

  1. PHASE 0 · NOW

    Foundations

    CLI, config, inventory, strict SSH transport, audit log.

  2. PHASE 1

    Read-only agent

    vio ask, vio check, redaction, injection evals.

  3. PHASE 2

    Plan & apply

    Typed change tools, lockout guard, rollback.

  4. PHASE 3

    Policy & fleet

    Policy files, groups, --json, more distros.

  5. PHASE 4

    Ecosystem

    Docker, Caddy/nginx, TLS, MCP, drift watch.
